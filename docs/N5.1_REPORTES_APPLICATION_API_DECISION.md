## Invariantes de aplicación/API

1. No crear un `ReporteCentralController`, `IReporteCentralService` o proxy equivalente únicamente para agrupar navegación.
2. El frontend puede enlazar o componer las capacidades existentes, pero no debe relajar la autorización de cada endpoint especializado.
3. Los filtros y semántica histórica deben seguir perteneciendo al contrato especializado dueño del dato; N5.1 no reconstruye históricos con valores maestros actuales sin evidencia.
4. Si aparece un caso de uso cross-domain material que realmente necesite un payload o transacción combinada, debe abrirse como gap explícito con contrato, pruebas y autorización propios; no se anticipa aquí.
5. No se modifican DTOs, endpoints productivos, permisos, persistencia, migraciones o servicios backend para satisfacer este child documental.

## Restricciones para N5.1.E — Frontend y UX

N5.1.E puede implementar una ruta/shell independiente y navegación hacia las capacidades existentes. No se prescribe un dashboard combinado ni peticiones concurrentes obligatorias: cualquier composición visual debe mantenerse dentro de los contratos ya autorizados y demostrar sus estados de loading/vacío/error/accesibilidad sin crear un seam backend artificial.
