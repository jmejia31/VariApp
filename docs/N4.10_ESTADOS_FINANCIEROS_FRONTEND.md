# Estados Financieros - Documentación Frontend (N4.10.H.1)

## 1. Resumen
Este documento describe la implementación verificada en el frontend del módulo de Estados Financieros, que permite generar y consultar información contable por período contable o por un rango de fechas. Solo se documenta comportamiento sustentado por el código y pruebas existentes en `Desarrollo`.

## 2. Componentes

### 2.1. `EstadosFinancierosComponent`
- **Ruta:** `frontend/src/app/features/estados-financieros/estados-financieros.component.ts`
- **Descripción:** Componente standalone de Angular (`app-estados-financieros`) que maneja la interfaz, el formulario de filtros y la presentación del resultado.
- **Estado y formulario:** usa `ReactiveFormsModule` con un `FormGroup` que contiene `tipo`, `modo`, `periodoContableId`, `fechaDesde` y `fechaHasta`.
- **Validación modo período:** `periodoContableId` debe estar informado y ser mayor a 0 antes de solicitar la generación.
- **Validación modo rango:** ambas fechas deben estar informadas y `fechaDesde` no puede ser posterior a `fechaHasta`.
- **Estado de ejecución:** activa `loading` antes de la solicitud y lo restablece mediante `finalize()`.
- **Cambio de modo:** limpia error/resultado y resetea los campos incompatibles del modo anterior.
- **Render estable:** `trackLinea()` usa `cuentaContableId` como identidad de las líneas.
- **Error seguro:** ante una respuesta fallida o error HTTP converge en el mensaje genérico `No fue posible generar el estado financiero. Intente nuevamente.`, sin exponer detalles internos del backend.

## 3. Servicio

### 3.1. `EstadoFinancieroService`
- **Ruta:** `frontend/src/app/services/estado-financiero.service.ts`
- **Responsabilidad:** comunicación con el API de estados financieros.
- **Método `generar`:** construye parámetros HTTP según el filtro proporcionado, incluyendo período contable o rango de fechas.
- **Frontera de seguridad:** `catchError` sustituye el detalle de la excepción por un error genérico para evitar propagación de información interna hacia la UI.

## 4. Modelos

### 4.1. Modelos de dominio
- **Ruta:** `frontend/src/app/core/models/estado-financiero.model.ts`
- El modelo define los contratos utilizados por la UI para filtro, respuesta, líneas y totales del estado financiero.
- El frontend consume `TipoEstadoFinanciero` y las estructuras asociadas sin redefinir contratos ad hoc en el componente.

## 5. Enrutamiento y permisos

### 5.1. Regresión de ruta
- **Evidencia:** `frontend/src/app/estados-financieros.route-regression.spec.ts`.
- La ruta canónica `estados-financieros` resuelve `EstadosFinancierosComponent`.
- La navegación está protegida por `authGuard` y `permisoGuard`.
- El contrato de autorización exige `modulo: 'Finanzas'` y `accion: 'Ver'`.
