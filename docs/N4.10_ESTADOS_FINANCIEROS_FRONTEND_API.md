# N4.10 — Estados Financieros — Contrato API Frontend

## 1. Alcance

Este documento certifica el contrato realmente consumido por el frontend para la generación de Estados Financieros dentro de `N4.10.H`. Se limita a la implementación vigente en `Desarrollo`; no introduce endpoints, parámetros, shapes de respuesta ni garantías backend no presentes en código.

## 2. Fuentes de verdad

- `frontend/src/app/services/estado-financiero.service.ts`
- `frontend/src/app/core/models/estado-financiero.model.ts`
- `frontend/src/app/core/models/api-response.model.ts`

## 3. Operación consumida por el frontend

### GET `${environment.apiUrl}/estados-financieros/{tipo}`

Método consumidor:

```text
EstadoFinancieroService.generar(
  tipo: TipoEstadoFinanciero,
  filtro: EstadoFinancieroFiltro
): Observable<ApiResponse<EstadoFinanciero>>
```

El segmento `{tipo}` proviene del enum `TipoEstadoFinanciero`:

1. `BalanceGeneral`
2. `EstadoResultados`
3. `BalanceComprobacion`
4. `LibroDiario`
5. `LibroMayor`
6. `FlujoEfectivo`

No se fija host ni ambiente: la base proviene de `environment.apiUrl`.

## 4. Parámetros de consulta

| Parámetro | Tipo frontend | Envío | Regla implementada |
| --- | --- | --- | --- |
| `periodoContableId` | `number` | Opcional | Se agrega cuando `filtro.periodoContableId != null`, convertido a string. |
| `fechaDesde` | `string` | Opcional | Se agrega cuando `filtro.fechaDesde` tiene valor. |
| `fechaHasta` | `string` | Opcional | Se agrega cuando `filtro.fechaHasta` tiene valor. |

El servicio no agrega parámetros llamados `periodo`, `desde` ni `hasta`.

## 5. Contrato de respuesta

El servicio tipa la respuesta como `ApiResponse<EstadoFinanciero>`.

`EstadoFinanciero` contiene:

| Campo | Tipo |
| --- | --- |
| `nombre` | `string` |
| `fechaInicio` | `string` |
| `fechaFin` | `string` |
| `lineas` | `EstadoFinancieroLinea[]` |
| `totales` | `EstadoFinancieroTotal[]` |

`EstadoFinancieroLinea` contiene `cuentaContableId`, `cuentaCodigo?`, `cuentaNombre?`, `saldo` y `esRaiz`.

`EstadoFinancieroTotal` contiene `etiqueta` y `valor`.

No se documentan campos como `saldoInicial`, `saldoFinal`, `totalIngresos`, `totalEgresos` o `moneda` porque no forman parte del modelo `EstadoFinanciero` vigente.

## 6. Frontera de error y sanitización

`EstadoFinancieroService.generar(...)` aplica `catchError` a la llamada HTTP y reemplaza cualquier detalle de excepción, validación o infraestructura por:

```text
No fue posible generar el estado financiero. Intente nuevamente.
```

La UI no debe depender de detalles crudos del backend para presentar errores al usuario.

## 7. Invariantes de integración

1. El endpoint efectivo es `${environment.apiUrl}/estados-financieros/{tipo}`.
2. `{tipo}` debe corresponder a un valor de `TipoEstadoFinanciero`.
3. `periodoContableId` solo se envía cuando no es `null`/`undefined`.
4. `fechaDesde` y `fechaHasta` solo se envían cuando tienen valor.
5. El consumidor debe tratar la respuesta como `ApiResponse<EstadoFinanciero>`.
6. Los errores crudos del transporte no se propagan por este servicio; se sustituyen por el mensaje genérico implementado.
7. Cambios futuros de endpoint, parámetros, modelos o frontera de error requieren sincronizar código, pruebas y esta documentación en el mismo cambio causal.

## 8. Corrección QA_TAKEOVER H.2

Ese contenido era evidencia insuficiente/inexacta para H.2 y no podía usarse para cierre de `N4.10.H`.

Este QA_TAKEOVER alinea el contrato documental con el código real y evita certificar un API frontend inexistente.
