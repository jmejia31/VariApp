# N4.10 — Estados Financieros — Contrato API Frontend

## 1. Alcance

Este documento certifica el contrato consumido por el frontend para la consulta de Estados Financieros dentro de `N4.10.H`. Su autoridad técnica se limita al comportamiento actualmente implementado en `EstadoFinancieroService` y a los modelos TypeScript asociados; no introduce endpoints, códigos HTTP ni campos que no estén presentes en el código de `Desarrollo`.

## 2. Fuente de verdad

- `frontend/src/app/services/estado-financiero.service.ts`
- `frontend/src/app/core/models/estado-financiero.model.ts`

## 3. Operación consumida por el frontend

### GET `/estados-financieros`

La URL efectiva se construye como:

```text
${environment.apiUrl}/estados-financieros
```

Método consumidor:

```text
EstadoFinancieroService.obtener(filtro: EstadoFinancieroFiltro)
```

El resultado esperado por el consumidor es:

```text
Observable<EstadoFinancieroResultado>
```

## 4. Parámetros de consulta

| Parámetro | Tipo frontend | Envío | Regla implementada |
| --- | --- | --- | --- |
| `periodo` | `string` | Siempre | Se agrega con `HttpParams.set('periodo', filtro.periodo)` |
| `desde` | `string` | Opcional | Solo se envía cuando `filtro.desde` tiene valor |
| `hasta` | `string` | Opcional | Solo se envía cuando `filtro.hasta` tiene valor |

Este contrato documenta únicamente la construcción del request en el servicio frontend. La validación semántica adicional pertenece a las capas que la implementen y no se presume aquí.

## 5. Contrato de respuesta

El frontend tipa la respuesta mediante `EstadoFinancieroResultado` con los siguientes campos:

| Campo | Tipo |
| --- | --- |
| `periodo` | `string` |
| `saldoInicial` | `number` |
| `saldoFinal` | `number` |
| `totalIngresos` | `number` |
| `totalEgresos` | `number` |
| `moneda` | `string` |

No se documentan campos adicionales porque no forman parte del modelo consumido actualmente por el frontend.

## 6. Frontera de error y sanitización

`EstadoFinancieroService.obtener(...)` aplica `catchError` a la llamada HTTP. Ante cualquier fallo recibido por esta frontera, el servicio no propaga al consumidor los detalles crudos del error HTTP o de infraestructura; emite un error controlado con el mensaje:

```text
No fue posible obtener el estado financiero solicitado. Intenta nuevamente.
```

Esta conducta preserva la frontera de redacción implementada para evitar que detalles internos del backend alcancen directamente la UI a través de este servicio.

## 7. Invariantes de integración

1. El consumidor frontend debe usar la ruta base definida por `environment.apiUrl`; este documento no fija hosts ni ambientes.
2. `periodo` forma parte de toda solicitud construida por el servicio.
3. `desde` y `hasta` no deben añadirse al query cuando no tengan valor.
4. El consumidor debe tratar la respuesta como `EstadoFinancieroResultado` y no depender de propiedades no declaradas en dicho modelo.
5. Los errores crudos del transporte no deben convertirse en mensajes visibles mediante este servicio; la frontera mantiene el mensaje genérico implementado.
6. Cambios futuros del endpoint, parámetros o shape de respuesta requieren sincronizar servicio, modelos, pruebas y este contrato en el mismo cambio causal.
