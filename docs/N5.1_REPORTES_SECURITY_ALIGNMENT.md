# N5.1.F — RBAC / Security Alignment — Centro de Reportes

Authority: `docs/VAEP_AUTHORITY.md`
Branch reviewed: `Desarrollo`
Parent: `N5.1.F`
Scope: security/RBAC alignment only. No privilege expansion, no production change, no deploy.

## Decision

The implemented Centro de Reportes must preserve the authorization contracts already enforced by the backend and frontend. No new role, permission, bypass, or broader privilege is introduced by N5.1.F.

### Administrative reports

Backend source: `backend/src/API/Controllers/ReportesAdministrativosController.cs`.

Observed contract:
- Controller requires authentication with `[Authorize]`.
- Base route is `reportes-administrativos`.
- `GET /reportes-administrativos/resumen`, `/usuarios-accesos`, `/roles-permisos`, and `/auditoria-resumen` require `ReportesAdministrativos:Ver`.
- `GET /reportes-administrativos/exportar/{tipo}` requires `ReportesAdministrativos:Exportar`.
- All actions additionally fail closed with `Forbid()` when the current user is not an administrator.
- Export is explicitly audited through `IAuditoriaService.RegistrarAsync`, recording module `ReportesAdministrativos`, action `Exportar`, report type, format and requested date range.

Frontend alignment:
- `/centro-reportes` requires `authGuard`.
- `/centro-reportes/administrativos` requires `permisoGuard` with `ReportesAdministrativos:Ver`.
- The shell/navigation only exposes administrative-report access when the runtime permission contract is satisfied; frontend visibility is not treated as an authorization boundary because backend authorization remains authoritative.

### Financial reports

Backend source: `backend/src/API/Controllers/EstadosFinancierosController.cs`.

Observed contract:
- Controller requires authentication with `[Authorize]`.
- Base route is `estados-financieros`.
- `GET /estados-financieros/{tipo:int}` requires `Finanzas:Ver`.
- Invalid financial-statement type values fail closed with `BadRequest`; valid values delegate to `IEstadoFinancieroService`.

Frontend alignment:
- `/centro-reportes/financieros` requires `permisoGuard` with `Finanzas:Ver`.
- Centro de Reportes does not widen the backend permission contract.

## Authorized / unauthorized paths

| Path | Required authenticated state | Required permission / additional condition | Expected unauthorized behavior |
| --- | --- | --- | --- |
| `/centro-reportes` | Authenticated | Shell only; child routes remain permission-gated | `authGuard` denies unauthenticated navigation |
| `/centro-reportes/administrativos` | Authenticated | `ReportesAdministrativos:Ver`; backend also requires administrator for administrative API actions | Frontend guard denies missing permission; backend returns forbidden when permission/admin contract is not satisfied |
| `/centro-reportes/financieros` | Authenticated | `Finanzas:Ver` | Frontend guard denies missing permission; backend authorization remains authoritative |
| `/reportes-administrativos/*` | Authenticated | `ReportesAdministrativos:Ver` or `:Exportar` depending on action; administrator required | Backend fails closed via authorization filter and/or `Forbid()` |
| `/estados-financieros/{tipo}` | Authenticated | `Finanzas:Ver` | Backend authorization denies missing permission |

## Audit / logging / correlation expectations

- Administrative export already has explicit audit persistence in `ReportesAdministrativosController.Exportar`.
- No claim is made that every report read currently produces an application-level audit entry; the reviewed controller does not explicitly register reads.
- No new correlation-id mechanism is introduced by this documentation-only task. Any request correlation remains governed by the existing platform middleware/infrastructure, not by N5.1.F.
- A future requirement for audit-on-read or stronger request-correlation evidence is a separate material gap and must not be represented as already implemented.

## Material gaps

1. No privilege expansion is required for N5.1.F; the current route/shell should continue to reuse `ReportesAdministrativos:Ver`, `ReportesAdministrativos:Exportar`, and `Finanzas:Ver` exactly as implemented.
2. Explicit application-level audit evidence exists for administrative exports. Equivalent explicit audit registration for report reads was not observed in the reviewed controllers and is therefore not certified here.
3. This task is documentation-only. No product code, schema, secret, deployment configuration, or production resource is changed.
