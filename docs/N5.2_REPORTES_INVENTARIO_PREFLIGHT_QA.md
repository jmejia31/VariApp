## Superficie observable
- Existen autoridades transaccionales de inventario para movimientos, conteos, ajustes y transferencias.
- `MovimientoInventario` conserva cantidad, stock anterior/nuevo, costo/precio unitario opcional, fecha, correlación y orígenes tipados, por lo que es una fuente base para Kardex e históricos.
- La analítica de rotación, aging/no-movement y consolidaciones transversales requiere contratos dedicados; no debe inferirse como ya implementada por existir endpoints operativos.
- La semántica de stock bajo/agotado debe seguir la autoridad física reconciliada en la evidencia específica de stock analytics, evitando tratar consultas legacy como equivalentes sin validación.

## Estrategia causal para fases siguientes
1. Tests unitarios para fórmulas/ventanas y contratos de filtrado.
2. Tests de integración API para scoping de almacén/sucursal, paginación, autorización y campos sensibles.
3. E2E mínimos desde Centro de Reportes para navegación, filtros, estados vacío/error y exportación cuando exista.
4. Regresión explícita de operaciones de inventario para garantizar lectura-only y ausencia de side effects.
5. Rollback por commit para cambios documentales; para implementación futura, rollback separado por contrato/API/UI sin tocar Producción desde VAEP.
