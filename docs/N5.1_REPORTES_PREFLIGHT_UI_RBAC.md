# N5.1 — Preflight UI / RBAC del Centro de Reportes

## Alcance

Inventario factual del estado actual de navegación y autorización relacionado con reportes. Este documento separa **comportamiento existente** de **restricciones de aceptación futuras**; no modifica UI, API, grants ni control-plane.

## 1. Comportamiento observable actual

### Frontend

- `ReportesAdministrativosComponent` existe en `frontend/src/app/features/reportes-administrativos/reportes-administrativos.component.ts`.
- El componente está embebido actualmente en `frontend/src/app/features/auditoria/auditoria-list.component.html` mediante `<app-reportes-administrativos>`.
- `frontend/src/app/app.routes.ts` expone la ruta `/auditoria` con `authGuard` + `permisoGuard` y `data: { modulo: 'Auditoria', accion: 'Ver' }`.
- En el árbol actual no se observa una ruta Angular independiente para `reportes-administrativos`.
- El servicio de reportes consume el backend `reportes-administrativos`; por tanto, poder navegar a `/auditoria` y estar autorizado por el backend son controles distintos.

### Backend

`backend/src/API/Controllers/ReportesAdministrativosController.cs`:

- tiene `[Authorize]` a nivel de controlador;
- usa `[Route("reportes-administrativos")]`;
- exige `ModuloSistema.ReportesAdministrativos` + `AccionPermiso.Ver` en lecturas;
- exige `ModuloSistema.ReportesAdministrativos` + `AccionPermiso.Exportar` en exportación;
- además aplica `if (!_currentUser.EsAdministrador) return Forbid();` en cada acción.

Endpoints observables:

| Método | Ruta | Permiso declarado |
| --- | --- | --- |
| GET | `/reportes-administrativos/resumen` | `ReportesAdministrativos:Ver` |
| GET | `/reportes-administrativos/usuarios-accesos` | `ReportesAdministrativos:Ver` |
| GET | `/reportes-administrativos/roles-permisos` | `ReportesAdministrativos:Ver` |
| GET | `/reportes-administrativos/auditoria-resumen` | `ReportesAdministrativos:Ver` |
| GET | `/reportes-administrativos/exportar/{tipo}` | `ReportesAdministrativos:Exportar` |

## 2. Gap de alineación actual

La navegación actual entra por una ruta autorizada como `Auditoria:Ver`, mientras los endpoints de reportes exigen `ReportesAdministrativos:*` y además administrador. Esto significa que **visibilidad/navegación frontend no equivale a autorización backend** y que un futuro centro independiente necesita una decisión explícita de alineación.

No se concluye aquí que el guard de administrador deba eliminarse: esa es una decisión de producto/seguridad que N5.1.B deberá resolver con requisitos aprobados. Tampoco se inventa un nuevo módulo de permisos.

## 3. Restricciones mínimas de aceptación para N5.1

1. Si se crea una ruta independiente de reportes, debe usar `authGuard` y `permisoGuard` con el módulo/acción que el backend realmente autorice.
2. El menú no puede ser el único mecanismo de seguridad; el backend debe seguir aplicando autorización fail-closed.
3. Debe existir una decisión explícita y testeada sobre si el centro independiente sigue siendo solo-administrador o si roles no administradores con `ReportesAdministrativos:Ver` pueden acceder.
4. Si el requisito aprobado permite roles no administradores, frontend y backend deben cambiar de forma coordinada; si el requisito conserva solo-administrador, debe mantenerse esa restricción en ambos lados sin bypass.
5. Exportar debe seguir siendo distinguible de Ver mediante `ReportesAdministrativos:Exportar` o el contrato equivalente aprobado.
6. Deben existir tests para: sin token, sin permiso, permiso de lectura, permiso de exportación, regla de administrador acordada, navegación directa por URL y ocultamiento de menú como UX (no como autorización).
7. La extracción del componente fuera de Auditoría no debe romper la bitácora ni la regresión existente de stale responses del componente de reportes.

## 4. Gaps que permanecen abiertos

- Ruta y entrada de menú independientes: no implementadas en este preflight.
- Política definitiva administrador vs RBAC puro: requiere decisión aprobada; no se presume.
- Tests específicos de navegación/autorización del futuro centro independiente: pendientes de la fase de implementación.
