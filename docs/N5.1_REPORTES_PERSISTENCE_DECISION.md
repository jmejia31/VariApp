# N5.1.C.1 — Reportes: aplicabilidad de persistencia y migraciones

## Decisión

**N/A: el alcance actual no requiere un esquema nuevo ni una migración de base de datos.**

El Centro de Reportes consume capacidades de lectura y exportación ya existentes. La inspección dirigida del repositorio vigente no muestra una necesidad material de introducir una entidad persistente adicional únicamente para consolidar esta navegación.

## Evidencia inspeccionada

- `backend/src/Infrastructure/Persistence/AppDbContext.cs`: el contexto ya expone las entidades operativas y contables usadas por los reportes; no existe una entidad específica requerida para persistir un “Centro de Reportes”.
- `backend/src/Infrastructure/Services/ReporteAdministrativoService.cs`: compone reportes mediante consultas sobre `Usuarios`, `Roles`, `Permisos`, `RolPermisos` y `RegistrosAuditoria`; las consultas de reporte observadas usan `AsNoTracking()`.
- `backend/src/Infrastructure/Services/EstadoFinancieroService.cs`: genera estados financieros consultando estructuras contables existentes (`CuentaContable`, `AsientoDetalles`, periodos y movimientos financieros) sin introducir persistencia adicional para el reporte generado.

## Brecha material

No se identifica una brecha de persistencia necesaria para este alcance. Funciones futuras como reportes programados, preferencias persistentes, snapshots históricos materializados o nuevas configuraciones guardadas serían requisitos distintos y deberán justificar explícitamente su modelo de datos y migración antes de implementarse.

## Límite de rollback

Este changeset es documental y no modifica `AppDbContext`, entidades, configuraciones de Entity Framework ni migraciones. Por tanto, su rollback no requiere restauración de base de datos ni reversión de migraciones; cualquier implementación funcional posterior deberá definir su propio rollback según los archivos que modifique.
