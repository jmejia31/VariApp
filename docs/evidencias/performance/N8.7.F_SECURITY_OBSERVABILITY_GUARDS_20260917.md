# N8.7.F — Performance — security and observability guards

Authority: `docs/VAEP_AUTHORITY.md`
Branch: `Desarrollo`
Scope: controlled N8.7 Development performance testing only.

## Security invariants

1. Use only authenticated Development identities and synthetic/test data scoped to the intended tenant.
2. Never use Production traffic, Production data or Production credentials.
3. Do not disable, weaken or bypass authentication, RBAC, tenant isolation, rate limiting, audit, validation, health controls or other security controls to obtain better performance numbers.
4. Never persist secret values, tokens, passwords, connection strings or sensitive payload bodies in harness source, logs, screenshots, receipts or performance evidence.
5. A cross-tenant access, authorization bypass, unsafe privilege expansion or sensitive-data exposure is an immediate FAIL/STOP condition, not an acceptable performance tradeoff.

## Operational stop conditions

Stop the controlled run if any of the following occurs:

- unexpected authorization or tenant-isolation failure;
- database-integrity risk or persistent write inconsistency;
- unsafe provider throttling/quota exhaustion or saturation that risks service stability;
- abnormal sustained 5xx/error behavior beyond the explicitly selected test profile;
- evidence that synthetic cleanup/reconciliation cannot be completed safely;
- any requirement to touch `main`, Production, PR #2 merge, DNS, certificates or secrets.

## Observability requirements

Record enough non-sensitive evidence to reproduce the test profile and understand the result: target Development service/route class, concurrency/volume profile, duration, terminal result, response/error observations, health status and relevant provider/resource observations when available. Correlation/audit evidence must not contain secret values or arbitrary sensitive payload bodies.

Measurements are observations for this Development run. They are not automatically a Production SLA/SLO and must not be presented as one.

## Cleanup and recovery

All generated test data must be synthetic/reversible. After a controlled write test, reconcile or remove generated fixtures where safe and verify the Development service returns to a healthy state. If a run is stopped for a security or integrity reason, preserve causal evidence and do not continue load until the defect is resolved or classified as an external blocker.

## Current-standard assessment

No product security/RBAC/audit/observability implementation change is required merely to permit N8.7 testing. This guard contract is the material N8.7.F deliverable. The actual authenticated load/stress/concurrency/endurance/volume proof remains mandatory in N8.7.G.
